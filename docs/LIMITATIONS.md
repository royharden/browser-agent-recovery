# Construction limits

This repository contains authored development source. Runtime is unverified.
Static parsing and source/diff review are the validation available for this
Dirty Mode construction milestone. No unit, integration, browser, fault/lag,
concurrency, isolation, admission, policy, scoring or report matrix has been run
as part of this work. Model cells remain not yet measured.

## Public browser boundary

The browser module declares the closed action/snapshot facade and the required
trusted bridge contract. No real browser/server bridge implementation is bound
by default. Missing bridge integration is unavailable; the facade does not
substitute direct authority calls or manufacture browser receipts. No browser,
server, Docker stack or service was launched for this milestone.

The in-process Python facade is not process isolation. A future worker needs a
bounded IPC interface, an actual fresh browser context and route/resource
enforcement, trusted request/clock/render lineage, preemptible transport
deadlines, and qualified ACL/egress/archive denial. Interface declarations and
lexical route checks do not demonstrate those protections. Trace/video capture
and live DOM reference installation also need real integration and validation.

## Authored scripted solver

`rlab.scripted.run_scripted` accepts only the explicit development goals for
ordering a numbered widget with quantity one, creating a general support
ticket with a numbered widget body, and deleting exactly a numbered widget.
It derives original target/form fields from that public goal and selects only
a unique visible role/name/row match. It uses public actions, observations and,
when the snapshot omits its version, complete current public history. Missing
or ambiguous controls and unavailable version evidence stop submission.

Ticket creation additionally requires a unique visible `textbox` named `Body`
in the `general` row and an acknowledged fill. HTML containing a textarea is
insufficient unless the public snapshot exposes its actionable textbox target.
The development Page now exposes Body textbox controls separately from its
mutation-button target list. The explicit in-process development bridge merges
those public controls into its bounded snapshot and projects filled text safely.
This is source projection, not real DOM installation or browser qualification.
Other bridges without a Body control still fail unavailable. The solver does
not pretend a missing field was filled.

The solver issues one original mutation action and delegates recovery to the
selected executor arm. It does not implement hidden families or inspect private
specifications, expected fixtures, evaluation answers or authority state.
`authored_scripted` is provenance, not independent reference truth. An authored
outcome, acknowledged action or `finish` does not establish task/oracle success.
Exceptions after dispatch preserve uncertainty and never justify resubmission.

## Explicit development and canonical profiles

The opt-in in_process_convenience bridge/backend reuses Authority/DevelopmentTask,
public scripted actions, task-owned lag history and synchronous authority-clock
terminal receipts. No real browser context, OS worker or sandbox is implied.
Default canonical operation remains unavailable; missing external admission
inputs are PENDING and explicit FAIL skips every execution mode. Nothing has run.

Supervisor/worker/private Unix admin source declares validated roots/identities,
fixed launch intent and bounded private messages. Canonical start refuses until
privileged launcher, filesystem/egress/namespace enforcement, descendant stop,
browser IPC, separate scorer access and denial probes actually join. Development
admin sealing and logical session.close are not those qualification receipts.

TrustedActionPortAdapter explicitly forwards caller request correlation and
absolute deadlines, capped by the existing executor budgets. Caller IDs cannot
choose run/epoch/root/origin; root intent remains trusted-generated. Reused or
malformed IDs refuse, and missing response metadata never gets a fabricated time.
D2 PublicObservation/ActionFeedback mapping requires an explicit accepted codec;
None is unavailable, and no implicit BrowserSession compatibility is asserted.
D3 owns matrix scheduling/runner; DevelopmentMatrixPort implements its single-row
lifecycle and JoinedDevelopmentOrchestration calls that fixed facade. Explicit
offline provider/action factories, genuine admission and prompt clearance remain
operator inputs. Provenance sidecars retain actual provider and loop receipts;
the evaluator report verifier alone does not cover those sidecars. Source joins
still require producer acceptance, and all runtime checks remain deferred.

The inherited-pipe source bounds its four-byte length prefix before body reads,
uses a serialized fixed offline broker owner and authorizes from an actual public
observation captured by the trusted side. No pipe, descriptor, process or provider
was exercised. The worker entry point continues to refuse activation because
canonical launch, enforcement and public browser IPC are unjoined. In-process
provider calls have no hard preemption guarantee from a pipe deadline.
